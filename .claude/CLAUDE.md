# 專案開發原則

## plan/task 溝通原則
- 交辦事項會寫於 plan.md，需要將規劃與執行細項寫於 task.md 中討論
- 完成的事項歸檔於 tasks 資料夾中，並將檔名加上時間，plan 則清空
- 完成的 task 會將 plan 內容寫於 task 上方，並寫摘要日後只需要讀摘要即可知道做過什麼事

## UI 設計
- 清爽專業設計：使用 tailwindcss + daisyui 統一 UI 風格，遵循現代網頁設計原則，保持界面簡潔專業
- tailwindcss 可以把常用的內容組合成一個 class，不一定要所有樣式都寫在 class 中
- 如果有產出多支 HTML，可以開始試著把共用 CSS/JS 抽出

## 技術原則
- 盡量開 agents 並行處理任務並回報給 main 的做法，保持 main 的暢通
- 使用簡單易用的開發語言，避免直接套用複雜的框架
- 復用既有資源：優先使用既有文件和組件，避免重複建立相似功能，禁止製造一次性文件浪費資源與 token
- 高效 Token 使用：避免重複說明，專注核心功能實現和問題解決

## 品質要求
- 階段性提交：每個完整階段進行 commit 和 README 更新
- 完整測試驗證：系統必須完整測試後才提供給用戶，確保功能正常運行

## 安全合規
- 設計架構與功能必須完整符合 ISO27001:2022，並注意機敏資料不得上傳
